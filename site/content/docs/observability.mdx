```xml
<dependency>
  <groupId>com.krizaka</groupId>
  <artifactId>krizaka-spring-boot-starter-observability</artifactId>
</dependency>
```

The starter brings the module, the actuator, OpenTelemetry tracing (Micrometer bridge + OTLP exporter) and the
Prometheus registry.

```yaml
krizaka:
  observability: { product: acme, service: orders, version: "@project.version@" }
```

The three names are **required**: a service that cannot say who it is does not start, and the error lists what is
missing. Every meter is tagged `product`, `service` and `version`.

## Defaults, at the lowest priority

Your `application.yml` still wins over each of them:

| Property | Default |
| :-- | :-- |
| `logging.structured.format.console` | `ecs` — JSON logs |
| `management.endpoints.web.exposure.include` | `health,info,prometheus` |
| `management.tracing.sampling.probability` | `0.1` |

Spans are exported once `management.opentelemetry.tracing.export.otlp.endpoint` is set.

## What the kit reports

| Where | Name | What |
| :-- | :-- | :-- |
| `/actuator/health` | `outbox` | per relayed store: last success, consecutive failures; **DOWN** at `krizaka.messaging.outbox.failure-threshold` failures in a row. `management.health.outbox.enabled=false` turns it off |
| `/actuator/health` | `dedup` | the claims table answers; **DOWN** otherwise — listeners would dead-letter. `management.health.dedup.enabled=false` turns it off |
| `/actuator/health` | `appConfig` | the app-config store answers (read directly, not from the cache), with the platforms and those in maintenance. `management.health.app-config.enabled=false` |
| `/actuator/info` | `krizaka` | `product`, `service`, `version` |
| observation | `krizaka.outbox.relay` | one batch of the outbox relay, tagged `krizaka.outbox.store` |
| observation | `krizaka.outbox.publish` | one publish, tagged with the exchange and the routing key |
| observation | `krizaka.messaging.dedup` | one `processOnce`, tagged `krizaka.consumer` and `outcome` (processed, duplicate, failed) |
| observation | `krizaka.idempotency` | one idempotent action, tagged with its scope and `outcome` (executed, replayed, rejected, failed) |

With the actuator each observation is a Micrometer timer — in Prometheus `krizaka_outbox_publish_seconds_count`, with an
`error` tag — and, with tracing on, a span: the Rabbit template's own span nests under the publish.

```text
sum by (outcome) (rate(krizaka_messaging_dedup_seconds_count[5m]))
```
