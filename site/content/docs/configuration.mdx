Every property below is in the metadata Spring Boot's configuration processor generates, so your IDE completes it in
`application.yml` with the same description and default. This page is generated from that metadata — never typed: each
repository holds `docs/configuration-metadata.json` equal to it with a test (`ConfigurationReferenceTest`) that also fails
on a property without a description or a default.

A property marked « no default » has none **on purpose**: a value only your service can give (its secret,
its names), or a choice the kit refuses to make for you (where messages are deduplicated, which origins may call). The
modules that need one say so at startup, with the property's name.

```yaml
krizaka:
  observability: { product: acme, service: orders, version: "@project.version@" }
  security.jwt.secret: ${KRIZAKA_JWT_SECRET}
  messaging:
    producer: orders
    dedup.store: jdbc
  idempotency.store: jdbc
```
