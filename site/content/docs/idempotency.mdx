---
title: Idempotency keys
description: krizaka-idempotency — an HTTP action runs at most once per Idempotency-Key; a retry replays its response.
---

```xml
<dependency>
  <groupId>com.krizaka</groupId>
  <artifactId>krizaka-spring-boot-starter-idempotency</artifactId>
</dependency>
```

A client whose connection dropped after your service accepted a request cannot tell whether it ran. Retrying blind pays
twice, not retrying loses the order. With an `Idempotency-Key` header the retry is safe — promoted from Orazaka, where
every paid run start works this way.

```yaml
krizaka:
  idempotency.store: jdbc
spring.sql.init.schema-locations: classpath:com/krizaka/idempotency/schema-postgresql.sql
```

```java
@PostMapping("/api/v1/orders")
ResponseEntity<Order> create(@RequestBody NewOrder order, @AuthenticationPrincipal Jwt caller,
    @RequestHeader(value = IdempotencyKeys.KEY_HEADER, required = false) String key) {
  return idempotency
      .execute(new IdempotentRequest("orders.create", caller.getSubject(), key, order),
          Order.class, () -> orders.create(order))
      .toResponse(HttpStatus.CREATED);
}
```

## The contract

| Request | Answer |
| :-- | :-- |
| first, with a key | the action runs; its response is stored in the action's transaction |
| retry, same key, same request | the stored response, with `Idempotent-Replayed: true` — the action does not run |
| same key, another request | `422` Problem Details, code `idempotency-key-reused` |
| two at once, same key | the second waits on the key, then replays the first |
| the action fails | nothing is recorded: the retry runs for real |
| no key | the action runs, every time |
| a malformed key | `400` Problem Details, code `invalid-idempotency-key` (1 to 255 visible ASCII characters) |

A key belongs to a scope and a subject: one customer's key never replays another's. The request is fingerprinted as the
SHA-256 of its canonical JSON, so the order of its fields is not a difference. Keys are kept `krizaka.idempotency.ttl`
(24 hours) and purged on a schedule.

## Proven

`JdbcIdempotencyIT` runs it on PostgreSQL — replay, reuse, rollback, two concurrent requests on one key, purge — and the
[example app](https://github.com/krizaka/krizaka-platform-kit/tree/main/examples/krizaka-idempotency-example) proves it
over HTTP. Every execution is observed as `krizaka.idempotency` (see [Observability](/observability)).
