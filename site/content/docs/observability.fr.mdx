title: Observabilité
description: krizaka-observability — noms de service obligatoires, logs ECS, Prometheus et OpenTelemetry par défaut.
---

```xml
<dependency>
  <groupId>com.krizaka</groupId>
  <artifactId>krizaka-spring-boot-starter-observability</artifactId>
</dependency>
```

Le starter apporte le module, l'actuator, le traçage OpenTelemetry (pont Micrometer + exportateur OTLP) et le registre
Prometheus.

```yaml
krizaka:
  observability: { product: acme, service: orders, version: "@project.version@" }
```

Les trois noms sont **obligatoires** : un service qui ne sait pas dire qui il est ne démarre pas, et l'erreur liste ce qui
manque. Chaque métrique porte les étiquettes `product`, `service` et `version`.

## Des défauts, à la priorité la plus basse

Ton `application.yml` l'emporte toujours sur chacun :

| Propriété | Défaut |
| :-- | :-- |
| `logging.structured.format.console` | `ecs` — logs JSON |
| `management.endpoints.web.exposure.include` | `health,info,prometheus` |
| `management.tracing.sampling.probability` | `0.1` |

Les spans sont exportés dès que `management.opentelemetry.tracing.export.otlp.endpoint` est défini.

## Ce que le kit rapporte

| Où | Nom | Quoi |
| :-- | :-- | :-- |
| `/actuator/health` | `outbox` | par stockage relayé : dernier succès, échecs consécutifs ; **DOWN** à `krizaka.messaging.outbox.failure-threshold` échecs d'affilée. `management.health.outbox.enabled=false` le coupe |
| `/actuator/health` | `dedup` | la table des réservations répond ; **DOWN** sinon — les listeners partiraient en lettre morte. `management.health.dedup.enabled=false` le coupe |
| `/actuator/health` | `appConfig` | le stockage app-config répond (lu directement, pas depuis le cache), avec les plateformes et celles en maintenance. `management.health.app-config.enabled=false` |
| `/actuator/info` | `krizaka` | `product`, `service`, `version` |
| observation | `krizaka.outbox.relay` | un lot du relais de l'outbox, étiqueté `krizaka.outbox.store` |
| observation | `krizaka.outbox.publish` | une publication, étiquetée avec l'exchange et la clé de routage |
| observation | `krizaka.messaging.dedup` | un `processOnce`, étiqueté `krizaka.consumer` et `outcome` (processed, duplicate, failed) |
| observation | `krizaka.idempotency` | une action idempotente, étiquetée avec son scope et `outcome` (executed, replayed, rejected, failed) |

Avec l'actuator chaque observation est un timer Micrometer — dans Prometheus `krizaka_outbox_publish_seconds_count`, avec
une étiquette `error` — et, traces activées, un span : celui du template Rabbit s'emboîte sous la publication.

```text
sum by (outcome) (rate(krizaka_messaging_dedup_seconds_count[5m]))
```
